# CLAUDE.md – Schlumpfwelt

Gemütliches Aufbauspiel im Browser für Kinder von 6–10 Jahren: Auf einer Insel gestalten sie ihr eigenes Dorf, die Bewohner arbeiten und verdienen Geld, davon kauft man Häuser, Deko und neue Bewohner. Kern-Spaß ist das Gestalten – die Wirtschaft ist Mittel zum Zweck, es gibt kein Game Over.

- **Quelle der Wahrheit:** `docs/ENTWICKLUNGSPLAN.md` (Leitplanken, Spieldesign, Technik, Roadmap)
- **Eigene Entscheidungen:** als Tabellenzeile in `docs/ENTSCHEIDUNGEN.md` (Datum, Meilenstein, Entscheidung, Begründung, Alternativen)
- **Live:** https://squantomas.github.io/Schlumpfwelt/ (jeder Push auf `main` wird veröffentlicht)

## Befehle

| Befehl | Zweck |
|---|---|
| `npm run dev` | Entwicklungsserver: http://localhost:5173/Schlumpfwelt/ (`npm run dev -- --host` für Tablet im WLAN) |
| `npm run build` | Produktions-Build nach `dist/` (ohne Typecheck) |
| `npm run preview` | `dist/` ausliefern: http://localhost:4173/Schlumpfwelt/ |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` | ESLint, keine Warnung erlaubt |
| `npm test` | Vitest einmalig (`npm run test:watch` im Watch-Modus) |
| `npm run check` | typecheck + lint + test + build – **muss vor jedem Push grün sein** |
| `npm run smoke` | Playwright-Smoke-Test, nur lokal (siehe unten; `-- --m4-only` nur die Shop-Prüfungen, `-- --m5-only` nur Speichern und Web-App, `-- --m6-only` nur die Bewohner, `-- --m7-only` nur Wohnen und Stimmung, `-- --m8-only` nur geführter Start, Eltern-Menü und Gute Nacht) |

CI (`.github/workflows/ci.yml`) prüft jeden Pull Request (bei jedem Push auf den PR-Branch); `.github/workflows/pages.yml` prüft `main` und veröffentlicht nur `main` auf GitHub Pages.

## Architekturregeln (verbindlich)

1. **`src/sim/` ist reines, deterministisches TypeScript:** kein Phaser, kein Browser, kein Netz, keine Timer, keine Wanduhr, kein `Math.random`. Zeit kommt nur über die Ticks, Zufall später nur über einen eigenen Seed-RNG in `src/sim/`. ESLint (`eslint.config.js`, Block `src/sim/**`) meldet als Fehler:
   - Imports von `phaser` und aus `scenes/`, `ui/`, `save/`, `parent/`, `main` sowie dynamische Imports,
   - Browser-, Netz- und Timer-Globals (`window`, `self`, `globalThis`, `document`, `navigator`, `location`, Storage/`indexedDB`/`caches`, `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `Worker`, `setTimeout`/`setInterval` (+ `clear…`), `queueMicrotask`, `requestAnimationFrame`/`requestIdleCallback`, `performance`, `crypto`, `Phaser`),
   - `Date.now`, `new Date()` ohne Argument, `Date()` und `Math.random`.

   `tests/architecture.test.ts` prüft jeden dieser Fälle. Die Regeln fangen nur direkte Zugriffe – was über Parameter hereingereicht wird, sieht ESLint nicht; das bleibt Review-Sache. Jede Sim-Datei hat Unit-Tests.
2. **Lesen + Befehle:** Szenen und UI lesen `simulation.state` (Typ `DeepReadonly<SimState>`, auf jeder Ebene schreibgeschützt) und ändern nur über `simulation.send({ type: … })`. Befehle werden zu Beginn des nächsten Ticks in Sendereihenfolge angewendet. Neuer Befehl = Union in `src/sim/commands.ts` erweitern, in `applyCommand` behandeln, testen.
3. **Feste Ticks:** 10 Ticks/s (`src/sim/clock.ts`). `simulation.update(deltaMs)` wird an genau einer Stelle aufgerufen (`IslandScene.update`) und gibt `alpha` ∈ [0, 1) zurück: die seit dem letzten Tick vergangene Zeit als Anteil eines Ticks (während der Pause 0). `(state.tick + alpha) * simulation.tickMs` ist eine gleichmäßig laufende Sim-Zeit für die Darstellung. Die Simulation hält nur den aktuellen Zustand; wer zwischen zwei Ticks überblenden will, merkt sich den vorherigen Zustand in der Szene selbst. Tick-Dauer immer über `simulation.tickMs`, nicht über die Konstante. Frames > 250 ms werden gekappt → nichts wird nachgeholt, kein Ertrag im Hintergrund.
4. **Texte:** Alle sichtbaren Texte stehen in `src/data/texts.de.json` (flache Schlüssel `bereich.name`) und werden nur über `t('key', params?)` aus `src/data/texts.ts` geholt. Keine Text-Literale in Szenen/UI.
5. **Theme (Markenrecht):** Alles Schlumpf-Spezifische (Spielname, Bewohner-Begriffe, Mützen …) steht nur in `src/data/theme.json`. Texte nutzen Platzhalter (`{gameName}`, `{creature}`, `{creatures}`, `{creaturesDative}`, `{creatureCompound}`, `{village}`, `{hat}`, `{hats}`). Ein Test verbietet die Markenbegriffe überall sonst in `src/` und `index.html` – auch in Kommentaren. Der `<title>` wird beim Build (`%GAME_NAME%`) und zur Laufzeit aus dem Theme gesetzt.
6. **Spieldaten als JSON** in `src/data/` (Gebäude, Waren, Preise …), damit Balancing ohne Code geht.
7. **Keine externen Server, kein Tracking, keine Werbung**, keine Fonts/Skripte von CDNs, keine Datenübertragung. Alles liegt lokal im Repo.
   - **Assets aus `public/` immer relativ laden** (`this.load.image('baum', 'assets/baum.png')`) oder über `import.meta.env.BASE_URL` (`` `${import.meta.env.BASE_URL}assets/baum.png` ``). Nie mit führendem `/` (`/assets/…`): Das Spiel liegt auf Pages unter `/Schlumpfwelt/`, ein absoluter Pfad ergibt dort einen 404, obwohl es lokal mit `npm run dev` funktioniert.
8. **Touch = Maus:** Jede Aktion funktioniert mit Finger und Maus gleich, nichts nur per Hover oder Rechtsklick. **Tippziele ≥ 48 CSS-px** (`MIN_TAP_SIZE` in `src/ui/style.ts`). Bauen per „Antippen + Bestätigen“ statt Drag & Drop.
9. **Layout in CSS-Pixeln:** Jede Szene ruft `onViewportChange(this, layout)` aus `src/ui/viewport.ts` auf – das setzt den Kamera-Zoom auf die Render-Skalierung (scharf auf Retina, max. 2×) und ruft `layout` bei jeder Größenänderung/Drehung neu auf. Hochkant und quer müssen funktionieren. Texte über `createLabel`/`setLabelSize` (`src/ui/label.ts`). Zusätzliche Kameras (z. B. die Weltkamera der IslandScene) multiplizieren ihren Zoom mit `renderScaleOf(scene)`. In der IslandScene liegt die Welt in `worldLayer` (Weltkamera, hinten), UI in `uiLayer` (Haupt-Kamera, vorn): neue Welt-Objekte nach `worldLayer`, neue UI nach `uiLayer`. **Welt-Objekte (Bäume, Felsen, Häuser) bekommen kein eigenes `setInteractive`:** Antippen läuft über das Szenen-Event `tile-tap` (`ISLAND_EVENTS.tileTap`, Kachelkoordinate) – nur Objekte im `uiLayer` blockieren das Ziehen der Kamera (`blocksCamera`). Tree- und Rock-Sprites liegen in `IslandScene.objects` (Map nach Kachelindex), `objectAt(x, y)` liefert sie. **Start (M3):** Die Kamera startet so, dass eine Kachel mindestens `minStartTileCssPx` (32) CSS-px groß ist, bei kleinen Schirmen aufs Startdorf zentriert (`startView`). **Bauen (M2):** Alle Bedienelemente platziert `layoutBuildUi` (`src/ui/buildLayout.ts`, getestet auf Überlappung und Rand); Werkzeugleiste unten (`toolbarLayout`: ab 320 px, bricht um; 4 Knöpfe: Weg, Shop, Verschieben, Abreißen), beim Platzieren links unten der Chip „zurück zum Shop“, Hinweisleiste oben mit ✕ (nur dieses ✕ beendet ein Werkzeug), ✓/✕ fest unten rechts über der Leiste, Zoom-Knöpfe oben rechts. Gebaut wird nur per Antippen + ✓: `BuildTool` (`src/ui/buildTool.ts`) hält Werkzeug und Vorschau und sendet `placeBuilding`/`placePaths`/`moveBuilding`/`demolish` (und die Insel-Befehle, `placementCommand`); `canPlace`/`checkPlacement` (`src/sim/buildings.ts`) gelten für Befehl und Vorschau, Wege laufen über `findRoute` (`src/sim/route.ts`, kürzeste baubare Route, Länge Teil der Suche, max. 40 Kacheln), Tipps auf Häuser treffen die Grafik (`buildingAtPoint`). `VillageView` gleicht die Darstellung über `state.revision` ab. Drücke auf Leisten bewegen die Kamera nie (`blocksPoint`). Farben nur in `style.ts`. **Wirtschaft (M3):** `inventory` (Taler und Waren, ganze Zahlen) und `production` (je Produktionsgebäude Fortschritt, Status `working`/`noPath`/`noNearby`/`waitingInput`/`idle`, `delivered`) stehen im Zustand; `tickProduction` läuft in `Simulation.step` (Regeln im Kopf von `src/sim/production.ts` und `economy.ts`). **Wege kosten nichts, Verschieben ist gratis, Abreißen erstattet die vollen Baukosten** (so sitzt man nie fest); Bäume und Felsen werden **nicht verbraucht**. Der Markt kauft auch Beeren (1 Taler, Reserve 4) und der Holzfäller kostet nur Taler: Beerengarten + Markt führen auch ohne Abriss immer wieder zu allem. Der Simulation geht die **rohe** Frame-Zeit (`simulationDelta`, `game.loop.rawDelta`), nur die `FixedStepClock` kappt; die Vorschau folgt dem Lager (`BuildTool.version`/`preview()` kennen die Lager-Signatur). `canPlace`/`checkPlacement` melden zusätzlich `noNearby` (keine Bäume/Felsen im Radius) und `cost` (mit den fehlenden Mengen). Die Lagerleiste oben links (`stockLayout`) schiebt die Hinweisleiste nach unten; `layoutBuildUi` rechnet auch Lagerleiste und Infokarte (Test auf 12 Schirmgrößen). Die Karten des Shops zeigen die Kosten (`CostRow`), Unbezahlbares ist ausgegraut, aber wählbar. Ein Tipp auf ein Produktionsgebäude (Grundriss, Dach oder Schild) öffnet im Anschauen die Infokarte (`BuildTool.inspectedId`), ein Tipp daneben schließt sie. Der Kamera-Mittelpunkt bleibt auf Land (plus 1 Kachel): `centerRegions` aus `landRegions` (`src/ui/cameraRegions.ts`). Kamera-Logik (Zoom, Grenzen, Gesten) steht ohne Phaser in `src/ui/cameraMath.ts`, `gestures.ts`, `cameraRig.ts`. **Shop (M4):** Der Knopf „Shop“ öffnet ein Feld im `uiLayer` (`ShopUI`, Lage aus `shopLayout`, rein und getestet auf 14 Schirmgrößen): oben vier Reiter (Häuser, Deko, Gebäude, Insel) und ein großes ✕, darunter die Karten; es deckt Werkzeugleiste, Zoom-Knöpfe, Hinweis und ✓/✕ ab (die Lagerleiste bleibt), Tipps auf die Welt tun dann nichts. Alle Karten eines Reiters sollen auf **eine Seite** passen (größte Karten zuerst); passt auch mit den kleinsten (88×72) nicht alles, wird mit **demselben Raster** (mehrere Reihen, so viele Karten pro Seite wie möglich, mindestens 4 bei 8–20 Artikeln) geblättert, die zwei großen Pfeile stehen links und rechts der **festen Zeile** unten im Feld. In dieser Zeile steht der Satz einer gesperrten Karte, bis etwas anderes angetippt wird (nichts läuft nach Zeit ab; ebenso bleiben Erklärungen der Hinweisleiste bis zum nächsten Tipp stehen, nur „Neu im Shop“ verschwindet nach 7 s). Ein Tipp auf die Welt neben dem Feld schließt den Shop und tut sonst nichts. Reiter und Werkzeugleiste zeigen ihr Wort ab 12 px, sonst bei allen nur das Symbol. Ein Tipp auf eine Karte schließt den Shop und startet das Platzieren (`BuildTool.chooseItem`, Werkzeug `place`; bezahlt wird erst beim Setzen, kein Besitz-Bestand); der getippte Platz bleibt, wenn man über den Chip einen anderen Artikel wählt. Karten sind `ok`, `dear` (grau, aber wählbar) oder `locked` (Schloss, Bedingung als Bild und „0/1“; ein Tipp zeigt den Satz und wählt nichts), berechnet in `src/ui/shopModel.ts`. Artikel, Reiter (`shop.category`), Preise, Reihenfolge und Freischaltung stehen in `buildings.json`; Texte der Artikel in `texts.de.json`. **Freischaltungen** (`unlock` in `buildings.json`: `count` Gebäude eines Typs, `houses`, `earned` Taler): `src/sim/unlocks.ts`, `state.unlocked` (Liste, einmal erreicht für immer frei; `count` verlangt einen Typ, der stehen kann – nicht Weg oder Inselartikel) und `state.earnedCoins` (der Markt zählt); `checkUnlocks` läuft nach jedem Tick und Befehlsstapel; `checkPlacement` meldet `locked` (nicht beim Verschieben). Neues im Shop: Meldung in der Hinweisleiste (`takeAnnouncements`), Stern am Shop-Knopf und an neuen Karten. Was zum Weiterkommen nötig ist (Holzfäller, Beerengarten, Markt), ist nie gesperrt. **Insel-Artikel** (Reiter „Insel“; `src/sim/island.ts`): Baum pflanzen, Fels setzen (Wiese → Wald/Fels, zählen für Holzfäller und Steinbruch), Strand aufschütten (Wasser am Land, nicht näher als 2 Kacheln am Kartenrand), Wiese anlegen (Strand → Wiese); eigene Befehle `plantTree`, `placeRock`, `fillLand`, `makeMeadow` mit `typeId` des Artikels (`placementCommand` baut sie), jede Änderung zählt als `revision`. Abreißen erstattet nur **selbst gepflanzte** Bäume und Felsen (`state.planted`: `{ index, type }`, die Erstattung folgt dem Artikel); natürliche bleiben, Strand und Wiese sind endgültig und ohne Erstattung. `IslandScene.syncTerrain` führt Bilder, Glitzern und Kamera-Bereiche nach und malt den Boden nur dort neu, wo er sich ändert: Der Boden besteht aus 8×8-Kachel-Blöcken (512 px) als eigene Texturen, die sich 4 px überlappen und deren äußerster Rand nicht gezeigt wird (`groundBlocks`, `paintGroundBlock`, `blocksTouching`, `REPAINT_REACH`); eine Änderung malt und lädt 1–4 Blöcke hoch (Kosten in `<html data-repaint>`).
10. **Platzhaltergrafik bis M8** (Formen/Canvas), aber schon in der finalen Kachelgröße. **Perspektive und Kachelgröße sind final:** Draufsicht auf ein quadratisches Raster, **Kachel 64×64 Welt-Pixel** (`TILE_SIZE` in `src/ui/style.ts`); Objekte (Bäume, Felsen, Häuser) in leichter Vorderansicht, dürfen nach oben über ihre Kachel hinausragen und werden nach y sortiert (Tiefe = y des Fußpunkts). Farben in `src/ui/style.ts`.
11. **Audio** ist bis M9 aus (`audio.noAudio` in `src/main.ts`); freigeschaltet wird es später im Startbildschirm-Tipp (`BootScene.startGame`), weil Tablets Ton erst nach einer Berührung erlauben.
12. **Speichern (M5):** Der Spielstand ist reine Datenarbeit in `src/sim/saveData.ts` (`toSaveData`, `fromSaveData(unbekannt)` → Zustand oder Grund `notSave`/`tooNew`/`broken`, wirft nie; `SAVE_VERSION`, `MIGRATIONS` als Kette reiner Funktionen `vN → vN+1`; Obergrenzen: Zahlen ≤ `MAX_SAFE_INTEGER`, Ids < 2³¹, Karte ≤ 2× Insel, 1000 Gebäude, 200 Produktionsgebäude). **Jede Änderung am Format hebt `SAVE_VERSION`, bekommt einen Migrationsschritt und einen Test; neue Zustandsfelder bekommen einen Normalisierer (Laden prüft alles) und stehen in `toSaveData`.** Ein Spielstand einer neueren Version wird nie geladen und nie überschrieben; ein **unlesbarer** wird vorher als Kopie gesichert (`backup` bleibt für immer, `backup-latest` wird überschrieben). IndexedDB, Dateien, Zeit, Sperren und Seitenereignisse leben nur in `src/save/` hinter `SaveStore` (Tests mit `MemoryStore`, die echte IndexedDB prüft der Smoke); Namen enthalten den Basispfad (`village-game/<Pfad>/`). **Autosave:** `Autosave.update(time)` einmal pro Frame aus `IslandScene.update`: eine Änderung von `revision` wird **sofort** (nächstes Bild) gespeichert – hartes Schließen darf den letzten Bau nicht kosten –, sonst jede Minute, `flush` beim Verstecken/Schließen (vorher wendet `Simulation.applyPending` wartende Befehle an); im Betrieb höchstens ein Schreibvorgang gleichzeitig (wer in der Zeit etwas verlangt, löst genau einen Nachschlag aus), nur beim **Verlassen der Seite** schreibt `flush` parallel daneben (`writeAlongside`: die Seite erlebt keinen Nachschlag mehr, IndexedDB hält die Reihenfolge); nach einem Import (`rebase`, zählt eine Generation hoch) setzt das Ergebnis eines noch laufenden Schreibvorgangs des alten Dorfs nicht mehr „gespeichert“; nie ein Ertrag im Hintergrund (nichts wird nachgeholt). **Das neueste Fenster speichert** (einheitlich mit und ohne Web Locks, `src/save/takeOver.ts`): Nur wenn die IndexedDB wirklich geht (geöffnet und gelesen innerhalb von 2 s), übernimmt das Fenster – ein Fenster mit Arbeitsspeicher-Speicher stiehlt nie eine Sperre und trägt keinen Besitzer ein. Übernehmen heißt: Besitzer-Eintrag `owner` setzen (`claim`: in **einer** Transaktion wird das Dorf des bisherigen Besitzers in den eigenen Schlüssel `data:<Fenster>` kopiert, der Besitzer gesetzt und erst dann Älteres entfernt – gelöscht wird nie, ohne dass im selben Zug feststeht, dass der Besitzer ein lesbares Dorf hat; scheitert oder dauert das über 2 s, wird es aufgegeben, `abandonClaim`), **danach** die Web Lock mit `steal` nehmen (`src/save/tabLock.ts`) – das alte Fenster erfährt es sofort (`AbortError`), ohne Web Locks beim nächsten Schreibvorgang. **Jedes Fenster schreibt nur in seinen eigenen Schlüssel** (`data:<Fenster>`, ein einziger `put`, ohne Rückfrage – das übersteht hartes Schließen; früher las ein Besitzer-Test erst und schrieb dann in einem Rückruf, den eine schließende Seite nicht mehr erlebte); gelesen wird das Dorf des Besitzers. Weil das alte Fenster nur in seinen eigenen Schlüssel schreibt, überschreibt es nie etwas Neueres; es prüft im selben Zug, ob es noch Besitzer ist (`OwnerLostError`). Das alte Fenster schreibt danach **nie wieder** (`Autosave.isLost`) und zeigt eine **feste Ebene über dem ganzen Spiel** (`LostOverlay`, `src/ui/lostLayout.ts`): ein Satz und ein großer Knopf „Hier weiterspielen“ (▶, mindestens 80 px); sie schluckt alle Tipps (nichts Ungespeichertes kann entstehen), ein Tipp auf den Knopf lädt die Seite neu (`location.reload()`), das Fenster übernimmt wieder und liest den neuesten Stand. Kein automatisches Neuladen beim Fokus (zwei offene Fenster würden sich ewig abwechseln). Hook: `data-menu="lost"`, Knopf `lost-play` in `data-menu-spots`. Das Dorf hat Grenzen (`src/sim/limits.ts`: 1000 Gebäude, 200 Produktionsgebäude, Ids unter 2³¹), die beim Bauen („Dein Dorf ist voll.“, `checkPlacement` → `full`) und beim Laden gleich gelten. **Adressregel:** `?seed=N` lädt und speichert **wie ohne Parameter** (der Seed wählt nur die Insel eines neuen Dorfs); **nur `&nosave=1`** schaltet Laden und Speichern ab (Tests und Smoke nutzen `?seed=1&nosave=1`). Ohne IndexedDB, mit einer neueren Version oder bei einem Lesefehler läuft das Spiel ohne Autosave und sagt es einmal in der Hinweisleiste. **Datei sichern und laden** steht hinter dem Zahnrad (`BuildUI` zeigt es nur im Anschauen, `VillageMenu` das Feld): Sichern geht auf iPad/iPhone übers Teilen-Blatt, sonst als Download; Laden ersetzt das Dorf erst nach ✓ (`Simulation.load`, danach `scene.restart()`; `create()` setzt alles zurück, was die Szene für die Tests veröffentlicht), Dateien über 2 MB werden nicht gelesen, der Dateiwähler hält den Knopf nie fest (`LatestOnly`). **iOS:** die Home-Bildschirm-App hat einen eigenen Speicher, getrennt von Safari – daher der Tipp-Satz im Menü (Datei sichern und in der App laden). 14. **Bewohner (M6):** Regeln im Kopf von `src/sim/residents.ts` und `walk.ts`, Zahlen in `src/data/residents.json`. Jeder Bewohner hat einen Namen (`names.json`; jeder Name einmal, bevor einer doppelt vorkommt, dann „Lumo 2“), eine Mütze und – wenn er arbeitet – den Beruf seines Gebäudes; Zufall nur über `state.residentRng` (Seed-RNG). **Jedes Produktionsgebäude hat sofort genau einen Arbeiter:** es nimmt den nächsten Bewohner ohne Arbeit, sonst kommt kostenlos einer mit dem Boot. Es arbeitet ab dem Setzen wie in M3 – Bewohner bremsen die Wirtschaft nie, **Tragen ist nur Anzeige** (das Lager bekommt die Ware am Ende der Runde, der Bewohner trägt ein Bild davon zum nächsten Markt). Abreißen der Arbeit macht arbeitslos (nächstes freie Gebäude), Verschieben oder Abreißen eines Ziels plant neu (vom Zielfeld des aktuellen Schritts aus, niemand springt). **Häuser** haben `capacity` (`buildings.json`: klein 2, groß 4, mit Garten 3); wer kein Zuhause hat, zieht von selbst ins nächste Haus mit Platz, Abreißen eines Hauses macht nur obdachlos, niemand wird weggeschickt. **Einladen** (Artikel `invite` im Reiter Häuser, `cost` 30 Taler): nur mit freiem Platz (`checkInvite` → `ok`/`full`/`noHouse`/`cost`; ohne Platz ist die Karte `noRoom` mit Haus und „2/2“, ein Tipp zeigt den Satz und wählt nichts), ✓ sendet `inviteResident` und geht zurück aufs Anschauen; ein Boot fährt vom Meer an die Küste beim Dorf (`seaWays`, `landingFor`: es taucht `boat.approachTiles` = 7 Kacheln vor der Küste auf, etwa 6–8 s Fahrt), der Gast steigt aus und geht nach Hause. Liegt die Fahrt nicht im freien Teil des Bildes, fährt die Kamera **nur im Anschauen** sanft hin (`IslandScene.followNewBoats` → `landingGlide` in `src/ui/boatCamera.ts` → `CameraRig.glideTo`, 0,6–1,6 s nach der rohen Bildzeit, je Bild höchstens 250 ms, springt nie; jede Berührung hält sie an, ebenso ein anderes Werkzeug, Shop, Menü oder eine Karte – `glideAllowed`). **Wege:** gewichtetes A* (`findWalk`, Kosten `walk.cost`: Weg 1, Wiese/Strand 3, Wald/Fels 5, Gebäude 200 nur ohne andere Wahl – niemand läuft über Dächer, um einen Umweg zu sparen –, kein Wasser) in ganzen Schritten pro Tick (60 pro Kachel; Weg 12, sonst 7, Boot 5, leer zurück 12); ohne Weg wartet ein Bewohner kurz (`waitTicks`) und versucht es wieder; liegt das Ziel auf einer anderen Landmasse (`landOf`/`canReach`: Nummer je Landkachel, einmal pro `revision` per Flood-Fill), lehnt `findWalk` sofort ab und er wartet `cutOffTicks` (60 s) – nach jeder Änderung des Dorfs (etwa Strand, der verbindet) prüft er sofort neu; `settleResidents` nach jedem Befehlsstapel und nach dem Laden. **Darstellung:** `ResidentView` (worldLayer) setzt die Figuren mit `residentPoint(state, resident, alpha)` zwischen zwei Ticks weiter (Tiefe = y des Fußpunkts, Ware über dem Kopf, Boot in zwei Teilen); **Antippen** im Anschauen über den Welt-Treffer (`residentAt`, `src/ui/residentHit.ts`: mindestens 24 CSS-px Radius um die Körpermitte; auf einem Gebäude, das im Anschauen antwortet – Produktionsgebäude, Haus ohne Weg, Schild; `BuildTool.buildingAnswersTap` –, höchstens 24 Welt-px, ab Zoom 1 also weiter 24 CSS-px, weit draußen behält das Gebäude sein Bild; der nächste gewinnt, kein `setInteractive`), dann `BuildTool.inspectResident` und `ResidentCard` an der Stelle der Infokarte (Name, Beruf, Mütze, Zuhause, Tätigkeit; ein Tipp daneben oder ✕ schließt; alle Zeilen in **einer** Schriftgröße, nie unter 12 px, lange Zeilen brechen um – `fitRows` in `residentCardLayout.ts`; auf flachen Schirmen eine kompakte Karte, höchstens 360 px breit, unten über der Werkzeugleiste). Die Einladen-Karte zeigt „Bewohner im Haus/Plätze“ (nie mehr als voll) und den Preis, wenn er passt. Spielstand seit Version 3 mit `residents`, `nextResidentId`, `boats`, `residentRng` (geprüft in `residentSave.ts`, höchstens 500 Bewohner; Version 4 siehe Regel 15). **Leistung:** Graphics immer über `addGraphics(scene)` (`FastGraphics`, sonst zerlegt Phaser jeden Bogen in 100 Punkte und schneidet ihn in jedem Bild neu in Dreiecke), Texte nur über `createLabel`/`setLabelSize` (zeichnen nur bei einer Änderung neu). `<html data-perf>` misst die Hauptthread-Zeit pro Bild (`PRE_STEP` bis `POST_RENDER`, `FrameStats`, letzte 300 Bilder); das ist ein **Hauptthread-JS-Budget pro Bild, nicht die Bildrate** (Headless zeichnet nur etwa 8 Bilder pro Sekunde); der Smoke prüft es mit 40 Bewohnern bei 4-facher CPU-Drosselung als Median aus 2 Fenstern zu je 300 Bildern (Grenze: Mittel 16 ms, p95 25 ms). 15. **Stimmung & Wohnen (M7):** Regeln im Kopf von `src/sim/mood.ts`, Zahlen in `residents.json` (`mood`, `food`). Die Stimmung (`happy`/`normal`/`sad`) wird **nicht gespeichert**, sondern aus dem Dorf berechnet (`moodOf`): +1 Deko bis `decoRadius` 2 Kacheln ums Haus, −1 weiter Weg (mehr als `farTiles` 12 Schritte von Tür zu Tür quer über die Kacheln, `wayToWork`), −1 Hunger; über 0 fröhlich, unter 0 traurig; ohne Zuhause zählen Deko und Weg nicht (höchstens normal). Deko und Türen rechnet `moodIndex` einmal pro Änderung (Schlüssel: Welt, Gebäude, Wege, `revision`), nicht in jedem Tick für alle. **Arbeitstempo:** `mood.pace` 120/100/80 % – eine Runde dauert `roundTicks(intervalTicks, pace)` (`production.ts`, `workPaces` pro Tick), Ertrag und Lager wie bisher, **nie Stillstand**, traurig mindestens etwa 75 %; der Weg wirkt **nur** über die Stimmung, nie direkt auf den Ertrag (Tragen bleibt Anzeige). **Essen:** jeder isst alle `mealTicks` eine Einheit (`food.goods`: Kuchen, sonst Beeren), das Dorf höchstens eine pro `mealGapTicks`; ohne Essen `hungry` (nur Stimmung), neuer Versuch nach `retryTicks`. Kein Auszug, nichts wird mit der Zeit schlimmer, nie Game Over; Beerengarten + Markt führen auch mit lauter Traurigen zu Geld (Balancing vorher/nachher in `tests/sim/residentsBalance.test.ts`). **Umziehen:** Befehl `assignHome` (`checkHome` → `ok`/`full`/`same`/`noHouse`/`noResident`, nicht im Boot): der Bewohner steht sofort an der Tür des neuen Hauses, das Zuhause bleibt; Abreißen macht nur obdachlos. Zwei Wege, beide Touch = Maus: **Ziehen** – im Anschauen (kein Shop/Menü, Zoom ≥ 0,5) hält ein Druck auf einen Bewohner ihn fest (`GestureTracker`-Modi `hold`/`carry`, Handler `grab`/`carry`/`drop`/`cancelCarry` in `src/ui/gestures.ts`, Treffer über `residentAt`), Bewegen trägt ihn (die Kamera steht still, eine offene Karte schließt), `ResidentDrag` (`src/ui/residentDrag.ts`, in `BuildTool`) sucht das Haus unter dem Finger über sein Bild (nur Häuser) und zeigt Vorschau `home` mit `carried` (rot bei voll/eigenem Haus, „2/2“ über dem Dach, kein ✓/✕). **Hürde gegen versehentliches Umziehen (Korrekturrunde 1):** ein Haus mit Platz ist erst gelb (`waiting`) und wird grün, wenn der Finger `DROP_DWELL_MS` (250 ms) darüber stand (`ResidentDrag.update(Bildzeit)` einmal pro Bild über `BuildTool.updateCarry`; ein anderes Haus fängt neu an) – nur Loslassen auf dem grünen Haus sendet `assignHome`; ein schnelles Wischen sagt „Halte {name} kurz über dem Haus, bis es grün wird.“, Loslassen ohne Haus (auch über Leisten oder Karte) „Lass {name} auf einem Haus los …“ (bleibt bis zum nächsten Tipp); ohne Bewegung bleibt es ein Tipp; daneben zieht der Finger wie immer die Kamera; unter Zoom 0,5 zieht ein Druck auf einen Bewohner die Kamera und sagt „Zoom näher heran, dann kannst du {name} tragen.“ (Rückruf `panStart` der Geste, Treffer streng wie auf einem Gebäude). Die Figur springt nie: Loslassen, Abbruch (zweiter Finger, touchcancel, Shop) und jeder `assignHome` (auch ✓ auf der Karte) lassen sie über `ResidentView.letGo` gleiten (0,28–0,9 s je nach Weg). Solange ein Finger auf der Welt liegt (`WorldCameraController.gestureActive`), fahren weder das Boots-Gleiten (`glideAllowed`) noch das Mausrad die Welt. Das „2/2“ steht über allem, über der getragenen Figur und über dem Schild „Weg fehlt“ (`homeLabelY` mit mehreren `AvoidBox`; `VillageView.homeLabelTop` für das Hingleiten). **„Umziehen“ auf der Karte** (`card-move`, mindestens 80×60 px, kompakt 80×52, Wort so groß wie die Zeilen, mindestens 14 px – `SquareButton.setCaptionFont`): Werkzeug `home` (`BuildTool.startMoveHome`), Haus antippen (über sein Bild, `houseAtPoint` – Blume oder Weg unter dem Dach verdecken es nicht; liegt es halb unter einer Leiste, gleitet die Kamera hin: `rectGlide` in `boatCamera.ts`, über `CameraRig.glideTo`, eine Berührung hält sie an) → Vorschau mit „0/2“ → ✓ zieht um und öffnet die Karte wieder, ✕ der Hinweisleiste führt zurück zur Karte; im Boot ist der Knopf abgeblendet, ein Tipp darauf setzt „{name} steigt gleich aus.“ an die Stelle des Tipps auf der Karte. **Darstellung:** Karte des Bewohners hochkant 6 Zeilen (Beruf, Mütze, Zuhause, Tätigkeit, Stimmung mit Grund, Tipp), quer kompakt 4 (Beruf, Zuhause, Stimmung, Tipp), Stimmungsbild an der Ecke des Bewohnerbilds, Schrift ≥ 12 px (getestet mit den längsten Texten auf 11 Schirmen; Platz bis 330 px hoch, kompakt bis 460 px breit, `RESIDENT_CARD_HEIGHT`); über dem Kopf ab und zu ein Herz (fröhlich) oder eine Wolke (traurig), 2,4 s von 15 s, nicht beim Tragen einer Ware, die Figur rechnet ihre Stimmung höchstens einmal pro Sekunde neu. Farben `mood*` in `style.ts`, Texte `mood.*`, `reason.*`, `tip.*`, `hint.home*`, `hint.drag*`. **Spielstand Version 4:** je Bewohner `meal` und `hungry` (Migration v3 → v4: alle satt, erste Mahlzeiten verteilt).

Auch `&nosave=1` zählt die Zeit (nur der Fortschritt des geführten Starts bleibt dort im Arbeitsspeicher, `keepTutorialInMemory`). **Tageskonto** (`DayClock`): `IslandScene.updateDay` reicht einmal pro Bild die rohe Bildzeit (`game.loop.rawDelta`, gekappt auf `MAX_FRAME_MS`) und den lokalen Tag (`localDayKey(new Date())`, einmal pro Sekunde) herein; gezählt wird nur, wenn die Seite sichtbar ist und weder Eltern-Menü noch „anderes Fenster“ offen sind, **nie aus Wanduhr-Differenzen**; ein neuer Kalendertag (auch Mitternacht im Spiel) beginnt ein neues Konto und beendet die Nacht. `ParentSession` speichert alle 5 s gezählter Zeit, bei jedem Ereignis und jeder Eltern-Aktion und beim Verlassen (`whenLeaving`); das neueste Fenster zählt (`stopWhen`: ein Fenster, das die Speicher-Sperre verloren hat, schreibt nicht mehr). **Phasen:** `day` (5 min vor dem Ende einmal `limit.warn` als Erklärung, ohne Countdown; nach einem Neuladen in diesem Fenster nicht noch einmal) → `dusk` (wärmer, dann dunkler; Shop, Menü, Karte, Werkzeug und Kamerafahrt enden; `setBedtime` – alle gehen heim, ohne Zuhause legen sie sich hin, wer im Boot sitzt, kommt erst an; mindestens 6 s, endet, wenn alle schlafen (`allAsleep`), spätestens nach 18 s) → `night` (`setPaused`, `applyPending`, `autosave.flush`: kein Takt, kein Ertrag) → nach +10 Minuten, einem neuen Limit oder einem neuen Tag `dawn` (3 s hell werden, `setBedtime` false, alle wachen versetzt auf) → `day`. Ist die Zeit beim Laden schon um, beginnt das Spiel sofort in der Nacht (`setBedtime instant`). Die **Schlafenszeit** `state.bedtime` lebt in der Simulation (Befehl `setBedtime { bedtime, instant? }`, `sleepOf`/`allAsleep`/`goToBed`/`wakeUp` in `residents.ts`), wird **nicht gespeichert** (keine neue `SAVE_VERSION`). **`NightLayer`** (uiLayer, über Leisten und Menü, unter Eltern-Menü und `LostOverlay`): zwei Farbflächen, nur die Deckkraft ändert sich (`nightLook`), Mond/Sterne/Satz einmal pro Größe gezeichnet; ab dem Abend schluckt eine Fläche alle Tipps (`covered` in der Szene: auch Ziehen, Mausrad, Tragen); in der Nacht nur der Schloss-Knopf `night-parent` (≥ 64 px) → Eltern-Menü. **Eltern-Menü** (`ParentPanel`, Ablauf `ParentFlow`, Lage `pinPadLayout`/`parentSettingsLayout`, getestet auf 14 Schirmen): „Für Eltern“ (`menu-parent`) hinter dem Zahnrad; Ziffernfeld (Tasten ≥ 48 px, hochkant ≥ 52 px, ⌫), beim ersten Mal PIN zweimal, falsche PIN = freundlicher Satz ohne Sperre, **„PIN vergessen?“ = Malaufgabe mit Zahlen von 12 bis 29** (dreistellige Antwort) → neue PIN; Einstellungen: Limit Aus/15/30/45/60/90 (Standard Aus), heute gespielt, „Heute noch 10 Minuten mehr“, „PIN ändern“, „Tutorial noch einmal“. **Geführter Start** (`src/ui/tutorial.ts`, rein und getestet; `TutorialGuide` zeichnet Hand und Leuchten einmal und bewegt sie nur, nimmt keine Tipps): nur ein **neues** Dorf beginnt ihn (`tutorialFor('new'|'loaded', …)`), ein geladenes oder importiertes hat keinen; Schritte erkennt `advanceTutorial` am Zustand, egal auf welchem Weg (Vergleichswerte = laufende Minima; „Taler“ verlangt neu verdiente; das Lob endet mit einem Tipp in einem späteren Bild); die Simulation weiß nichts davon; Ziehen ist kein Pflichtschritt. Der Satz steht in der Hinweisleiste mit ✕ zum Überspringen (`tutorial-skip`, ≥ 48 px) – danach und nach dem Lob für immer aus. **Vorrang** (`pickHint`): Shop → Karte → Meldung (Neu im Shop, Fehler, Erklärung, Tragen) → Werkzeug-Hinweis → geführter Start; er verdrängt nie etwas und kommt immer wieder. Hooks: `data-tutorial` (JSON `status`, `step`, `index`, `shown`, Hand `hx`/`hy`/`below` in CSS-px), `data-parent` (`closed` oder `<Modus>[:<Satzschlüssel>]`, Modi `newPin`/`repeatPin`/`enterPin`/`question`/`settings`), `data-parent-text` (der Satz im Feld), `data-limit` (JSON `phase`, `used`/`allowed` in s, `limit`, `extra`, `warned`, `day`, `store`, `pin`, `saves`, `failures`), `data-night` (`dark`, `warm`, `sky`, `blocks`), `data-bedtime` (1/0); in `data-menu-spots` `menu-parent`, `parent-panel`, `parent-close`, `pin-0`…`pin-9`, `pin-back`, `pin-forgot`, `limit-<Minuten>` (mit `active`), `parent-extra`, `parent-pin`, `parent-tutorial`, `night-parent`; in `data-ui` `tutorial-skip`.

## Konventionen

- Code-Bezeichner und Code-Kommentare **Englisch**; sichtbare Texte, Doku, Commit-Messages und Testnamen **Deutsch**.
- TypeScript strict (+ `noUncheckedIndexedAccess`), kein `any`, Typ-Importe mit `import type`.
- Tests liegen in `tests/` und spiegeln `src/`. Tests **nie** deaktivieren oder überspringen (`.skip`/`.only`/`.todo` sind per Lint verboten).
- Kleine Commits; vor jedem Push `npm run check` grün und Smoke-Test ohne Konsolenfehler.
- Szenen-Keys in `src/scenes/keys.ts`; jede Szene ruft in `create()` `markActiveScene(…)` auf.
- Neue Abhängigkeiten nur mit klarem Grund (im PR begründen). **Playwright nie als Abhängigkeit hinzufügen.**
