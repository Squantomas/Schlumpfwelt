# CLAUDE.md – Schlumpfwelt

Gemütliches Aufbauspiel im Browser für Kinder von 6–10 Jahren: Auf einer Insel gestalten sie ihr eigenes Dorf, die Bewohner arbeiten und verdienen Geld, davon kauft man Häuser, Deko und neue Bewohner. Kern-Spaß ist das Gestalten – die Wirtschaft ist Mittel zum Zweck, es gibt kein Game Over.

- **Quelle der Wahrheit:** `docs/ENTWICKLUNGSPLAN.md` (Leitplanken, Spieldesign, Technik, Roadmap)
- **Eigene Entscheidungen:** als Tabellenzeile in `docs/ENTSCHEIDUNGEN.md` (Datum, Meilenstein, Entscheidung, Begründung, Alternativen)
- **Live:** https://squantomas.github.io/Schlumpfwelt/ (jeder Push auf `main` wird veröffentlicht)

## Befehle

| Befehl | Zweck |
|---|---|
| `npm run dev` | Entwicklungsserver: http://localhost:5173/Schlumpfwelt/ (`npm run dev -- --host` für Tablet im WLAN) |
| `npm run build` | Produktions-Build nach `dist/` (ohne Typecheck) |
| `npm run preview` | `dist/` ausliefern: http://localhost:4173/Schlumpfwelt/ |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` | ESLint, keine Warnung erlaubt |
| `npm test` | Vitest einmalig (`npm run test:watch` im Watch-Modus) |
| `npm run check` | typecheck + lint + test + build – **muss vor jedem Push grün sein** |
| `npm run smoke` | Playwright-Smoke-Test, nur lokal (siehe unten; `-- --m4-only` nur die Shop-Prüfungen, `-- --m5-only` nur Speichern und Web-App, `-- --m6-only` nur die Bewohner, `-- --m7-only` nur Wohnen und Stimmung, `-- --m8-only` nur geführter Start, Eltern-Menü und Gute Nacht, `-- --m9-only` nur Bilder, Rasterersatz und Ton) |
| `npm run prompts` | Prompt-Vorlagen der Bilder nach `docs/assets/` schreiben (aus `src/art/catalog.ts`; ein Test prüft, dass sie auf dem Stand sind) |

CI (`.github/workflows/ci.yml`) prüft jeden Pull Request (bei jedem Push auf den PR-Branch); `.github/workflows/pages.yml` prüft `main` und veröffentlicht nur `main` auf GitHub Pages.

## Architekturregeln (verbindlich)

1. **`src/sim/` ist reines, deterministisches TypeScript:** kein Phaser, kein Browser, kein Netz, keine Timer, keine Wanduhr, kein `Math.random`. Zeit kommt nur über die Ticks, Zufall später nur über einen eigenen Seed-RNG in `src/sim/`. ESLint (`eslint.config.js`, Block `src/sim/**`) meldet als Fehler:
   - Imports von `phaser` und aus `scenes/`, `ui/`, `save/`, `parent/`, `audio/`, `art/`, `main` sowie dynamische Imports,
   - Browser-, Netz- und Timer-Globals (`window`, `self`, `globalThis`, `document`, `navigator`, `location`, Storage/`indexedDB`/`caches`, `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `Worker`, `setTimeout`/`setInterval` (+ `clear…`), `queueMicrotask`, `requestAnimationFrame`/`requestIdleCallback`, `performance`, `crypto`, `Phaser`),
   - `Date.now`, `new Date()` ohne Argument, `Date()` und `Math.random`.

   `tests/architecture.test.ts` prüft jeden dieser Fälle. Die Regeln fangen nur direkte Zugriffe – was über Parameter hereingereicht wird, sieht ESLint nicht; das bleibt Review-Sache. Jede Sim-Datei hat Unit-Tests.
2. **Lesen + Befehle:** Szenen und UI lesen `simulation.state` (Typ `DeepReadonly<SimState>`, auf jeder Ebene schreibgeschützt) und ändern nur über `simulation.send({ type: … })`. Befehle werden zu Beginn des nächsten Ticks in Sendereihenfolge angewendet. Neuer Befehl = Union in `src/sim/commands.ts` erweitern, in `applyCommand` behandeln, testen.
3. **Feste Ticks:** 10 Ticks/s (`src/sim/clock.ts`). `simulation.update(deltaMs)` wird an genau einer Stelle aufgerufen (`IslandScene.update`) und gibt `alpha` ∈ [0, 1) zurück: die seit dem letzten Tick vergangene Zeit als Anteil eines Ticks (während der Pause 0). `(state.tick + alpha) * simulation.tickMs` ist eine gleichmäßig laufende Sim-Zeit für die Darstellung. Die Simulation hält nur den aktuellen Zustand; wer zwischen zwei Ticks überblenden will, merkt sich den vorherigen Zustand in der Szene selbst. Tick-Dauer immer über `simulation.tickMs`, nicht über die Konstante. Frames > 250 ms werden gekappt → nichts wird nachgeholt, kein Ertrag im Hintergrund.
4. **Texte:** Alle sichtbaren Texte stehen in `src/data/texts.de.json` (flache Schlüssel `bereich.name`) und werden nur über `t('key', params?)` aus `src/data/texts.ts` geholt. Keine Text-Literale in Szenen/UI.
5. **Theme (Markenrecht):** Alles Schlumpf-Spezifische (Spielname, Bewohner-Begriffe, Mützen …) steht nur in `src/data/theme.json`. Texte nutzen Platzhalter (`{gameName}`, `{creature}`, `{creatures}`, `{creaturesDative}`, `{creatureCompound}`, `{village}`, `{hat}`, `{hats}`). Ein Test verbietet die Markenbegriffe überall sonst in `src/` und `index.html` – auch in Kommentaren. Der `<title>` wird beim Build (`%GAME_NAME%`) und zur Laufzeit aus dem Theme gesetzt.
6. **Spieldaten als JSON** in `src/data/` (Gebäude, Waren, Preise …), damit Balancing ohne Code geht.
7. **Keine externen Server, kein Tracking, keine Werbung**, keine Fonts/Skripte von CDNs, keine Datenübertragung. Alles liegt lokal im Repo.
   - **Assets aus `public/` immer relativ laden** (`this.load.image('baum', 'assets/baum.png')`) oder über `import.meta.env.BASE_URL` (`` `${import.meta.env.BASE_URL}assets/baum.png` ``). Nie mit führendem `/` (`/assets/…`): Das Spiel liegt auf Pages unter `/Schlumpfwelt/`, ein absoluter Pfad ergibt dort einen 404, obwohl es lokal mit `npm run dev` funktioniert.
8. **Touch = Maus:** Jede Aktion funktioniert mit Finger und Maus gleich, nichts nur per Hover oder Rechtsklick. **Tippziele ≥ 48 CSS-px** (`MIN_TAP_SIZE` in `src/ui/style.ts`). Bauen per „Antippen + Bestätigen“ statt Drag & Drop.
9. **Layout in CSS-Pixeln:** Jede Szene ruft `onViewportChange(this, layout)` aus `src/ui/viewport.ts` auf – das setzt den Kamera-Zoom auf die Render-Skalierung (scharf auf Retina, max. 2×) und ruft `layout` bei jeder Größenänderung/Drehung neu auf. Hochkant und quer müssen funktionieren. Texte über `createLabel`/`setLabelSize` (`src/ui/label.ts`). Zusätzliche Kameras (z. B. die Weltkamera der IslandScene) multiplizieren ihren Zoom mit `renderScaleOf(scene)`. In der IslandScene liegt die Welt in `worldLayer` (Weltkamera, hinten), UI in `uiLayer` (Haupt-Kamera, vorn): neue Welt-Objekte nach `worldLayer`, neue UI nach `uiLayer`. **Welt-Objekte (Bäume, Felsen, Häuser) bekommen kein eigenes `setInteractive`:** Antippen läuft über das Szenen-Event `tile-tap` (`ISLAND_EVENTS.tileTap`, Kachelkoordinate) – nur Objekte im `uiLayer` blockieren das Ziehen der Kamera (`blocksCamera`). Tree- und Rock-Sprites liegen in `IslandScene.objects` (Map nach Kachelindex), `objectAt(x, y)` liefert sie. **Start (M3):** Die Kamera startet so, dass eine Kachel mindestens `minStartTileCssPx` (32) CSS-px groß ist, bei kleinen Schirmen aufs Startdorf zentriert (`startView`). **Bauen (M2):** Alle Bedienelemente platziert `layoutBuildUi` (`src/ui/buildLayout.ts`, getestet auf Überlappung und Rand); Werkzeugleiste unten (`toolbarLayout`: ab 320 px, bricht um; 4 Knöpfe: Weg, Shop, Verschieben, Abreißen), beim Platzieren links unten der Chip „zurück zum Shop“, Hinweisleiste oben mit ✕ (nur dieses ✕ beendet ein Werkzeug), ✓/✕ fest unten rechts über der Leiste, Zoom-Knöpfe oben rechts. Gebaut wird nur per Antippen + ✓: `BuildTool` (`src/ui/buildTool.ts`) hält Werkzeug und Vorschau und sendet `placeBuilding`/`placePaths`/`moveBuilding`/`demolish` (und die Insel-Befehle, `placementCommand`); `canPlace`/`checkPlacement` (`src/sim/buildings.ts`) gelten für Befehl und Vorschau, Wege laufen über `findRoute` (`src/sim/route.ts`, kürzeste baubare Route, Länge Teil der Suche, max. 40 Kacheln), Tipps auf Häuser treffen die Grafik (`buildingAtPoint`). `VillageView` gleicht die Darstellung über `state.revision` ab. Drücke auf Leisten bewegen die Kamera nie (`blocksPoint`). Farben nur in `style.ts`. **Wirtschaft (M3):** `inventory` (Taler und Waren, ganze Zahlen) und `production` (je Produktionsgebäude Fortschritt, Status `working`/`noPath`/`noNearby`/`waitingInput`/`idle`, `delivered`) stehen im Zustand; `tickProduction` läuft in `Simulation.step` (Regeln im Kopf von `src/sim/production.ts` und `economy.ts`). **Wege kosten nichts, Verschieben ist gratis, Abreißen erstattet die vollen Baukosten** (so sitzt man nie fest); Bäume und Felsen werden **nicht verbraucht**. Der Markt kauft auch Beeren (1 Taler, Reserve 4) und der Holzfäller kostet nur Taler: Beerengarten + Markt führen auch ohne Abriss immer wieder zu allem. Der Simulation geht die **rohe** Frame-Zeit (`simulationDelta`, `game.loop.rawDelta`), nur die `FixedStepClock` kappt; die Vorschau folgt dem Lager (`BuildTool.version`/`preview()` kennen die Lager-Signatur). `canPlace`/`checkPlacement` melden zusätzlich `noNearby` (keine Bäume/Felsen im Radius) und `cost` (mit den fehlenden Mengen). Die Lagerleiste oben links (`stockLayout`) schiebt die Hinweisleiste nach unten; `layoutBuildUi` rechnet auch Lagerleiste und Infokarte (Test auf 12 Schirmgrößen). Die Karten des Shops zeigen die Kosten (`CostRow`), Unbezahlbares ist ausgegraut, aber wählbar. Ein Tipp auf ein Produktionsgebäude (Grundriss, Dach oder Schild) öffnet im Anschauen die Infokarte (`BuildTool.inspectedId`), ein Tipp daneben schließt sie. Der Kamera-Mittelpunkt bleibt auf Land (plus 1 Kachel): `centerRegions` aus `landRegions` (`src/ui/cameraRegions.ts`). Kamera-Logik (Zoom, Grenzen, Gesten) steht ohne Phaser in `src/ui/cameraMath.ts`, `gestures.ts`, `cameraRig.ts`. **Shop (M4):** Der Knopf „Shop“ öffnet ein Feld im `uiLayer` (`ShopUI`, Lage aus `shopLayout`, rein und getestet auf 14 Schirmgrößen): oben vier Reiter (Häuser, Deko, Gebäude, Insel) und ein großes ✕, darunter die Karten; es deckt Werkzeugleiste, Zoom-Knöpfe, Hinweis und ✓/✕ ab (die Lagerleiste bleibt), Tipps auf die Welt tun dann nichts. Alle Karten eines Reiters sollen auf **eine Seite** passen (größte Karten zuerst); passt auch mit den kleinsten (88×72) nicht alles, wird mit **demselben Raster** (mehrere Reihen, so viele Karten pro Seite wie möglich, mindestens 4 bei 8–20 Artikeln) geblättert, die zwei großen Pfeile stehen links und rechts der **festen Zeile** unten im Feld. In dieser Zeile steht der Satz einer gesperrten Karte, bis etwas anderes angetippt wird (nichts läuft nach Zeit ab; ebenso bleiben Erklärungen der Hinweisleiste bis zum nächsten Tipp stehen, nur „Neu im Shop“ verschwindet nach 7 s). Ein Tipp auf die Welt neben dem Feld schließt den Shop und tut sonst nichts. Reiter und Werkzeugleiste zeigen ihr Wort ab 12 px, sonst bei allen nur das Symbol. Ein Tipp auf eine Karte schließt den Shop und startet das Platzieren (`BuildTool.chooseItem`, Werkzeug `place`; bezahlt wird erst beim Setzen, kein Besitz-Bestand); der getippte Platz bleibt, wenn man über den Chip einen anderen Artikel wählt. Karten sind `ok`, `dear` (grau, aber wählbar) oder `locked` (Schloss, Bedingung als Bild und „0/1“; ein Tipp zeigt den Satz und wählt nichts), berechnet in `src/ui/shopModel.ts`. Artikel, Reiter (`shop.category`), Preise, Reihenfolge und Freischaltung stehen in `buildings.json`; Texte der Artikel in `texts.de.json`. **Freischaltungen** (`unlock` in `buildings.json`: `count` Gebäude eines Typs, `houses`, `earned` Taler): `src/sim/unlocks.ts`, `state.unlocked` (Liste, einmal erreicht für immer frei; `count` verlangt einen Typ, der stehen kann – nicht Weg oder Inselartikel) und `state.earnedCoins` (der Markt zählt); `checkUnlocks` läuft nach jedem Tick und Befehlsstapel; `checkPlacement` meldet `locked` (nicht beim Verschieben). Neues im Shop: Meldung in der Hinweisleiste (`takeAnnouncements`), Stern am Shop-Knopf und an neuen Karten. Was zum Weiterkommen nötig ist (Holzfäller, Beerengarten, Markt), ist nie gesperrt. **Insel-Artikel** (Reiter „Insel“; `src/sim/island.ts`): Baum pflanzen, Fels setzen (Wiese → Wald/Fels, zählen für Holzfäller und Steinbruch), Strand aufschütten (Wasser am Land, nicht näher als 2 Kacheln am Kartenrand), Wiese anlegen (Strand → Wiese); eigene Befehle `plantTree`, `placeRock`, `fillLand`, `makeMeadow` mit `typeId` des Artikels (`placementCommand` baut sie), jede Änderung zählt als `revision`. Abreißen erstattet nur **selbst gepflanzte** Bäume und Felsen (`state.planted`: `{ index, type }`, die Erstattung folgt dem Artikel); natürliche bleiben, Strand und Wiese sind endgültig und ohne Erstattung. `IslandScene.syncTerrain` führt Bilder, Glitzern und Kamera-Bereiche nach und malt den Boden nur dort neu, wo er sich ändert: Der Boden besteht aus 8×8-Kachel-Blöcken (512 px) als eigene Texturen, die sich 4 px überlappen und deren äußerster Rand nicht gezeigt wird (`groundBlocks`, `paintGroundBlock`, `blocksTouching`, `REPAINT_REACH`); eine Änderung malt und lädt 1–4 Blöcke hoch (Kosten in `<html data-repaint>`).
10. **Grafik (seit M9 eigene SVGs, Regel 17):** Jedes Bild hat einen festen Schlüssel in `src/art/catalog.ts` und wird aus den Tokens in `style.ts` gezeichnet; Regeln für Aussehen und Bewegung in `docs/STIL_LEITFADEN.md` (Umriss = Farbe + 55 % Tinte, nie Schwarz; Licht von links oben, Schatten nach rechts unten; runde Formen; kein Text im Bild; keine fremden Figuren). **Perspektive und Kachelgröße sind final:** Draufsicht auf ein quadratisches Raster, **Kachel 64×64 Welt-Pixel** (`TILE_SIZE` in `src/ui/style.ts`); Objekte (Bäume, Felsen, Häuser) in leichter Vorderansicht, dürfen nach oben über ihre Kachel hinausragen und werden nach y sortiert (Tiefe = y des Fußpunkts). Farben in `src/ui/style.ts`.
11. **Ton (M9):** Phasers eigener Ton bleibt aus (`audio.noAudio` in `src/main.ts`); alle Geräusche und die Musik macht `AudioEngine` (`src/audio/`, Regel 17). Freigeschaltet wird sie im Startbildschirm-Tipp (`BootScene.startGame` → `audio.unlock()`), weil Tablets Ton erst nach einer Berührung erlauben; vorher und ohne Web Audio ist alles still, ohne Fehler.
12. **Speichern (M5):** Der Spielstand ist reine Datenarbeit in `src/sim/saveData.ts` (`toSaveData`, `fromSaveData(unbekannt)` → Zustand oder Grund `notSave`/`tooNew`/`broken`, wirft nie; `SAVE_VERSION`, `MIGRATIONS` als Kette reiner Funktionen `vN → vN+1`; Obergrenzen: Zahlen ≤ `MAX_SAFE_INTEGER`, Ids < 2³¹, Karte ≤ 2× Insel, 1000 Gebäude, 200 Produktionsgebäude). **Jede Änderung am Format hebt `SAVE_VERSION`, bekommt einen Migrationsschritt und einen Test; neue Zustandsfelder bekommen einen Normalisierer (Laden prüft alles) und stehen in `toSaveData`.** Ein Spielstand einer neueren Version wird nie geladen und nie überschrieben; ein **unlesbarer** wird vorher als Kopie gesichert (`backup` bleibt für immer, `backup-latest` wird überschrieben). IndexedDB, Dateien, Zeit, Sperren und Seitenereignisse leben nur in `src/save/` hinter `SaveStore` (Tests mit `MemoryStore`, die echte IndexedDB prüft der Smoke); Namen enthalten den Basispfad (`village-game/<Pfad>/`). **Autosave:** `Autosave.update(time)` einmal pro Frame aus `IslandScene.update`: eine Änderung von `revision` wird **sofort** (nächstes Bild) gespeichert – hartes Schließen darf den letzten Bau nicht kosten –, sonst jede Minute, `flush` beim Verstecken/Schließen (vorher wendet `Simulation.applyPending` wartende Befehle an); im Betrieb höchstens ein Schreibvorgang gleichzeitig (wer in der Zeit etwas verlangt, löst genau einen Nachschlag aus), nur beim **Verlassen der Seite** schreibt `flush` parallel daneben (`writeAlongside`: die Seite erlebt keinen Nachschlag mehr, IndexedDB hält die Reihenfolge); nach einem Import (`rebase`, zählt eine Generation hoch) setzt das Ergebnis eines noch laufenden Schreibvorgangs des alten Dorfs nicht mehr „gespeichert“; nie ein Ertrag im Hintergrund (nichts wird nachgeholt). **Das neueste Fenster speichert** (einheitlich mit und ohne Web Locks, `src/save/takeOver.ts`): Nur wenn die IndexedDB wirklich geht (geöffnet und gelesen innerhalb von 2 s), übernimmt das Fenster – ein Fenster mit Arbeitsspeicher-Speicher stiehlt nie eine Sperre und trägt keinen Besitzer ein. Übernehmen heißt: Besitzer-Eintrag `owner` setzen (`claim`: in **einer** Transaktion wird das Dorf des bisherigen Besitzers in den eigenen Schlüssel `data:<Fenster>` kopiert, der Besitzer gesetzt und erst dann Älteres entfernt – gelöscht wird nie, ohne dass im selben Zug feststeht, dass der Besitzer ein lesbares Dorf hat; scheitert oder dauert das über 2 s, wird es aufgegeben, `abandonClaim`), **danach** die Web Lock mit `steal` nehmen (`src/save/tabLock.ts`) – das alte Fenster erfährt es sofort (`AbortError`), ohne Web Locks beim nächsten Schreibvorgang. **Jedes Fenster schreibt nur in seinen eigenen Schlüssel** (`data:<Fenster>`, ein einziger `put`, ohne Rückfrage – das übersteht hartes Schließen; früher las ein Besitzer-Test erst und schrieb dann in einem Rückruf, den eine schließende Seite nicht mehr erlebte); gelesen wird das Dorf des Besitzers. Weil das alte Fenster nur in seinen eigenen Schlüssel schreibt, überschreibt es nie etwas Neueres; es prüft im selben Zug, ob es noch Besitzer ist (`OwnerLostError`). Das alte Fenster schreibt danach **nie wieder** (`Autosave.isLost`) und zeigt eine **feste Ebene über dem ganzen Spiel** (`LostOverlay`, `src/ui/lostLayout.ts`): ein Satz und ein großer Knopf „Hier weiterspielen“ (▶, mindestens 80 px); sie schluckt alle Tipps (nichts Ungespeichertes kann entstehen), ein Tipp auf den Knopf lädt die Seite neu (`location.reload()`), das Fenster übernimmt wieder und liest den neuesten Stand. Kein automatisches Neuladen beim Fokus (zwei offene Fenster würden sich ewig abwechseln). Hook: `data-menu="lost"`, Knopf `lost-play` in `data-menu-spots`. Das Dorf hat Grenzen (`src/sim/limits.ts`: 1000 Gebäude, 200 Produktionsgebäude, Ids unter 2³¹), die beim Bauen („Dein Dorf ist voll.“, `checkPlacement` → `full`) und beim Laden gleich gelten. **Adressregel:** `?seed=N` lädt und speichert **wie ohne Parameter** (der Seed wählt nur die Insel eines neuen Dorfs); **nur `&nosave=1`** schaltet Laden und Speichern ab (Tests und Smoke nutzen `?seed=1&nosave=1`). Ohne IndexedDB, mit einer neueren Version oder bei einem Lesefehler läuft das Spiel ohne Autosave und sagt es einmal in der Hinweisleiste. **Datei sichern und laden** steht hinter dem Zahnrad (`BuildUI` zeigt es nur im Anschauen, `VillageMenu` das Feld): Sichern geht auf iPad/iPhone übers Teilen-Blatt, sonst als Download; Laden ersetzt das Dorf erst nach ✓ (`Simulation.load`, danach `scene.restart()`; `create()` setzt alles zurück, was die Szene für die Tests veröffentlicht), Dateien über 2 MB werden nicht gelesen, der Dateiwähler hält den Knopf nie fest (`LatestOnly`). **iOS:** die Home-Bildschirm-App hat einen eigenen Speicher, getrennt von Safari – daher der Tipp-Satz im Menü (Datei sichern und in der App laden). Texte `menu.*` und `save.*` in `texts.de.json`.
